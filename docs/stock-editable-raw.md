# Camera metadata and editable RAWs on the stock path

`tools/raw_media.py` extracts source calibration without decoding pixels and
packages little-endian unpacked Bayer as uncompressed DNG, or an existing
stock VC-5 payload as GPR. GPR wrapping performs no new encode. It preserves
the compressed payload exactly; an editable DNG contains decoded Bayer values.
Neither operation performs demosaicking, display rendering or CNN inference.
The production Python tools use only the standard library.

```sh
python3 tools/raw_media.py metadata source.GPR --sample-bits 14 --output calibration.json
python3 tools/raw_media.py export frame.vc5 --metadata calibration.json --kind gpr --output frame.gpr
python3 tools/raw_media.py export frame.raw --metadata calibration.json --kind dng --output frame.dng
```

The metadata schema is `gpr.raw_metadata.v1`. Its width, height, sample_bits
and CFA describe the actual Bayer counts. Calibration records carry typed TIFF
values as little-endian bytes compressed with zlib and base64, preserving exact
rational numerators/denominators and opaque opcode bytes. Image, EXIF and GPS
directories are separate; output offsets are rebuilt. Source SHA-256 records
provenance. Supported image tags are an explicit whitelist in `raw_media.py`.

The reader accepts classic little- or big-endian TIFF/DNG/GPR and a single
unambiguous Bayer image, including SubIFDs with global camera/profile values
in IFD0. BigTIFF and linked/interoperability EXIF directories are unsupported.
Unknown/private image tags and storage/digest tags are not copied; their codes
are reported in `omitted_image_tags`. MakerNotes and DNGPrivateData can carry
source-relative offsets and are omitted. This is calibrated export with an
explicit preservation boundary, not preservation of every vendor-private tag.
Source calibration may include camera serial numbers and GPS information.

Validation checks required calibration tags and their types/counts, CFA,
black/white ranges, white balance, finite rationals, nonsingular color matrices,
active/crop bounds, duplicate/structural tags and decompression limits. It does
not infer whether a user-selected source is the correct calibration for an
unrelated frame, nor interpret all optional DNG opcodes. The caller must supply
the matching source. Editable DNG packaging supports all four Bayer phases and
12/14/16-bit counts in 16-bit words. This does not extend the stock encoder's
supported input formats. GPR wrapping accepts its matching four-channel RAW
header, RGGB/GBRG and 12/14-bit domains; it does not validate every entropy code.

## Capture and sequence export

The capture replay frontend accepts one `--source-metadata calibration.json`
per `--input frame.raw`, in input order. It copies that source's complete
metadata into each accepted frame under `raw_metadata`, alongside source and
attempt indices. The native capture ABI continues to treat metadata as opaque
bounded bytes; the replay option expects trusted JSON generated by the metadata
tool. Typed validation happens in the export consumer. Large metadata that
exceeds the native 64 KiB record limit requires an external sidecar.

```sh
build-runtime/gpr_capture_app --input one.raw --source-metadata one.json \
  --input two.raw --source-metadata two.json --output clip.gvid \
  --quality 3 --frames 12 --leased --submit-timeout-ms 10000
python3 tools/stock_video.py extract clip.gvid --out-dir editable \
  --decoder build-runtime/source/app/stock_video/stock_video --editable both
```

Export chooses the complete per-frame `raw_metadata`, then clip metadata, then
the explicit `--metadata-file` default. A selected override replaces the whole
calibration; fields are not silently merged. Geometry/domain disagreement is an
error. A frame limit still validates framing and typed calibration throughout
the recording. Receipts bind payload, metadata, decoded RAW and export hashes.
Outputs use new paths and do not overwrite existing files.
An unsuccessful command can leave earlier frame files; a successful receipt
with `complete: true` certifies the complete recording.

`--editable gpr` needs no decoder and preserves original compressed bytes.
`--editable dng` needs the decoder; `both` writes both forms. Current video
decoding is RGGB14. The existing optional `restore --editable dng` packages
the reconstructed counts, preserving source calibration and recording model
identity in the receipt. Reconstructed GPR export is rejected because it needs
a new encode. Source noise calibration is not a measured post-CNN noise model;
stock-matched reconstruction quality remains unapproved and optional.

## Verification

`GPR_BUILD_MEDIA_TESTS=ON` adds `raw_media` to CTest; build `gpr_tools`,
`stock_video` and `gpr_capture_app` first. Tests additionally need numpy and
tifffile. They check independent TIFF/EXIF/GPS reads, big-endian SubIFDs,
every Bayer phase/bit-domain packaging combination, invalid calibration,
independent historical stock fixtures, SDK RAW decode, sequence calibration
switching, exact GPR payloads and decoded DNG pixel identity.

`tools/benchmark_editable.py` reproduces source-metadata extraction, capture,
export and independent payload/calibration/EXIF/GPS/pixel checks. It also
decodes each exported GPR through the SDK and compares its Bayer values to
the original recorded payload's decode. Use paired `--source` and `--raw`
arguments, plus `--capture`, `--decoder`, `--sdk`, and a new `--output-dir`.
This is still-derived replay and offline export, not sensor truth or a live
capture/display/CNN throughput measurement.

## Pi 5 receipt, 2026-10-28

The 12-frame run in `stock-editable-pi5` alternated the supplied GP011728 and
GPAB1094 4096×3072 sources at stock Q3. All 12 accepted/written frames passed
the payload, supported calibration, EXIF/GPS, Bayer DNG and SDK GPR decode
checks. The two decoded hashes also match the earlier independent stock
reference decodes. Calibration values remain local to the Pi; the published
receipt contains hashes rather than camera serial/GPS values.
The exported real-source DNG also opened and rendered through macOS Image I/O
(`sips`); the review image was inspected locally. Its source orientation is
preserved, independently of the legacy SDK preview's mirror convention.

| Measurement | Result |
|---|---:|
| Capture process wall time, including setup | 0.8052 s |
| Offline extract/decode/DNG+GPR export process | 7.0624 s |
| Offline export wall throughput | 1.6991 frames/s |
| Replay overruns | 0 / 12 |
| Replay completion deadline misses | 11 / 12 |

Capture used leased input, four slots, 192 MiB requested workspace and USB SSD.
It was unpaced and short; its 30.26 buffered fps and 23.24 durable fps do not
establish reliable 30 fps. Export timing includes subprocess startup, full
clip hashing/checksums, native RAW decoding and writes of payload, RAW, GPR,
DNG and receipt files. It excludes the subsequent independent verification
pass and final export-storage fsync. No CNN or display ran during capture.
This run followed completed builds/tests; the earlier diagnostic run that
overlapped a sanitizer build is not used for performance claims.

Full SDK testing also exposed inherited frontend input/output buffer leaks.
The port fixes cleanup on success and handled errors, propagates output-write
failure, and recognizes compiler byte-order macros when building the old DNG
SDK on Linux ARM64. Those fixes are covered by editable workflow and leak tests.
EXIF enum storage also now represents the DNG SDK's absent-value sentinel and
TIFF values such as light source 14. Sparse and real-source metadata dumps pass
UBSan; the checked C field widths and layout remain unchanged.

## Optional CNN to editable DNG check

`stock-editable-cnn-mac.json` records a real 1x inference/export test using the
explicit BIBO1x stock-Q3 checkpoint (SHA-256 `df22af43…`) on Apple M5 Max MPS.
One 12 MP frame took 0.442 s for tiled inference (256-plane-pixel cores,
64-pixel halos); all 12 recording frames were inspected and the end marker
verified. The DNG pixels equal the reconstructed RAW exactly and the supported
source calibration/EXIF remains intact. This is an offline workstation test.

Relative to the already-compressed camera replay reference, stock decode PSNR
was 62.74 dB and the CNN result 52.48 dB. These are not clean sensor targets or
evidence of perceptual improvement. The checkpoint remains unapproved for
stock-video restoration; nothing enables it by default. Full model selection,
held-out quality/temporal tests and 2x reconstruction remain on the rebuild.
